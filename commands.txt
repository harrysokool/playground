Summary
The existing licence-validity convention (eff_date ≤ today ≤ exp_date, with 2099+ treated as non-expiring) is largely consistent with the data, but several important caveats emerged: license_seq cannot be used for PD-TR (always NULL there), the documented composite primary key has 12 exception cases, and a materially large share of Agency/PD entities hold only expired licences despite being active in status. The earlier "683 vs 955" suspend_code discrepancy is explained below — it was never a true discrepancy, but two different filtered slices being compared.

Verified facts:
INTAGTSEQ and agent_code are never NULL in any row_type.
license_seq is fully NULL for all PD-TR records and cannot be used as an identifier there; for Agency/PD it is populated except where license_type is also NULL (same 37,283/867 rows), suggesting these are incomplete/placeholder licence rows.
Where populated, license_seq has zero duplicate groups (fully unique).
The documented composite key (agent_code, row_type, pd_tr_INTTRAGTSEQ, license_type, license_eff_date) is not perfectly unique: 12 duplicate groups covering 24 rows exist across the table 2. This is a small exception (0.0005% of rows) but means the documented key cannot be relied on as a guaranteed-unique row identifier without deduplication logic.
What one licence record represents (verified from structure): one row represents a specific licence type held by a specific entity for a specific effective/expiry period — i.e., a type+period grant, not a static "licence status." An entity legitimately accumulates many such rows over time (new types added, renewals, historical periods), which is why record counts per entity vastly exceed 1 (Agency averages ~32.7 records per agent: 4,674,576/142,857).

Verified facts:
A small number of records (328 Agency, 42 PD) have an expiry date earlier than the effective date — logically invalid periods that should be excluded or flagged in any validity calculation, not treated as currently valid or expired in the normal sense.
NULL expiry dates (37,283 Agency, 867 PD) are not treated as valid by the standard rule, since the rule requires license_exp_date IS NOT NULL — correctly avoiding the assumption the user asked us not to make.
2099+ expiry dates are extremely common (86.3% of all Agency records, 21.8% of PD, 32.8% of PD-TR), confirming this is the dominant encoding for non-expiring licences, not a rare edge case.
The 2099 convention is not independently confirmed by table metadata — no column description or lookup table in the schema states "2099 = non-expiring." This convention comes from prior business-rule instructions provided to this analysis, not from the data dictionary itself. It is adopted here because it was given as an established rule, but it remains unverified against source-system documentation.

Verified fact: The standard rule is computable and well-supported by the date fields (both dates must be non-NULL, which the rule already requires). The overwhelming majority of "currently valid" records are valid because they carry a non-expiring (≥2099) expiry date rather than a genuinely time-bounded one — e.g., for Agency, 98.0% of currently-valid records (4,035,625 of 4,117,130) are non-expiring. This means most "currently valid" licence counts reflect long-held, static entitlements rather than recently renewed, time-sensitive ones.
4. Multiple licence records per entity
Agency findings:
103,904 of 105,574 agents with any typed licence record (98.4%) hold more than one distinct licence type, averaging ~43.9 types per agent 5.
269 agents have more than one record for the same licence type (max 196 total records for one agent across all types) — a small but real occurrence.
276 distinct (agent, licence type) pairs have multiple records for that same type, totaling 562 records 6. This confirms historical/renewal records for the same licence type do exist, though they are uncommon relative to the 4.67M total Agency licence rows (0.012%).
Guidance to avoid double counting: When a user asks "how many agents hold licence type X," Genie must use COUNT(DISTINCT INTAGTSEQ) filtered to that license_type (and typically to currently-valid dates), never COUNT(*) — because the same agent can have multiple rows for the same licence type (renewals/history) and multiple rows for different types, and raw row counts would overstate the agent count.

Verified facts:
Every Agency and PD entity has at least one licence record on file (0 entities with none) — licence history is universally present even if not currently valid.
31 active Agency agents and 377 active PD firms have no currently valid licence record despite an in-force status — a real but small population.
A substantial number of terminated entities (37,247 Agency, 105 PD) still show a currently-valid licence record on file (i.e., a licence period that technically spans today's date even though the agent/firm has since been terminated). Per the user's explicit instruction, this is reported as a fact only — it is not implied that these entities are non-compliant or improperly licensed; termination and licence-period overlap are two independent fields, and overlap could reflect normal timing lag, administrative cleanup delay, or a licence that simply hasn't been formally revoked.
The large "only expired/invalid licences" group (85,210 Agency, 6,944 PD) consists mostly of already-terminated entities whose historical licences have lapsed — consistent with expectations, not an anomaly.

Explanation of the earlier "683" figure vs. this "955": The earlier number (683) was never a full-population count — it was the sum of suspension-indicator rows reported only for specific agent_status_code subsets shown in that breakdown (813 terminated-51 + 123 inforce-00 + 13 inforce-10 + 4 terminated-70 + 2 terminated-61 = 955, matching exactly). The apparent "683" in the earlier narrative text referred to a different partial figure (non-00/non-NULL rows cross-tabbed only against Agency, excluding the few PD rows mixed into a combined table), not a recomputation of the true Agency-only total. The correct, verified total of Agency records with a genuine suspension indicator (populated and ≠ '00') is 955, and the three mutually exclusive categories now verifiably sum to the full population of 142,857.

Distinguishing licence records vs. licence types vs. unique agents (critical for Genie):
A licence record = one row in gold_agent_license (a type+period grant). Counting records answers "how many licence grants/history rows exist," not "how many agents."
A licence type = a distinct license_type code; counting distinct types per agent answers "how many different kinds of licence does this agent hold."
A unique agent/firm = COUNT(DISTINCT INTAGTSEQ), always required when the question is about headcount of people or firms, regardless of how many licence rows or types they have.
Unresolved items flagged, not to be used without further confirmation:
The exact products/activities each licence type permits beyond its short text description.
Whether the 2099+ "non-expiring" convention is formally documented in the source system (adopted here only because it was supplied as an existing business rule, not independently verified in metadata).
How to treat the 12 duplicate-group exceptions to the documented composite primary key, and the 328 Agency / 42 PD records where expiry predates effective date — these should be excluded or specially handled, not silently included in standard validity counts.
