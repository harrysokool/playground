Key Finding: INTPERSONSEQ Does Not Represent the Technical Representative — It Represents the Firm
The hypothesis is confirmed. On PD-TR rows, INTPERSONSEQ is tied to the broker firm, not to the individual technical representative. The most likely individual-level identifier is pd_tr_ia_code, and pd_tr_INTTRAGTSEQ is a record/relationship-level key, not a person-level key.

This means pd_tr_INTTRAGTSEQ is a finer-grained record sitting underneath a given IA code / access ID — consistent with it being a relationship or transaction-level key, while pd_tr_ia_code (and pd_tr_access_id) look like the more stable, individual-level credential.
3. Does the same pd_tr_ia_code appear under multiple firms (INTAGTSEQ)?
Yes — verified. Of 15,063 distinct pd_tr_ia_code values, 8,762 (58%) appear under more than one INTAGTSEQ, with a maximum of 229 distinct firms for a single IA code and an average of ~2.0 firms per IA code 3.
This confirms an IA-licensed individual can legitimately be registered as a technical representative at multiple broker firms simultaneously — a real-world pattern consistent with IA licensing rules, not a data error by itself.

However, there remain 60 firms where many TR IDs map to a single IA code, meaning some fraction of the TR-ID multiplicity is not explained by distinct IA-credentialed individuals and remains unexplained by the fields examined here.
5. Is INTPERSONSEQ associated with the firm rather than the representative?
Confirmed — this is the central finding.
Per distinct INTPERSONSEQ (483 total): average 1.67 firms, but average 40.8 distinct pd_tr_ia_code values, 52.9 distinct pd_tr_access_id values, and 76.2 distinct pd_tr_INTTRAGTSEQ values per person — one person-level INTPERSONSEQ is associated with dozens of different individual-looking credentials, which is not plausible for a single real individual 5.
Directly testing the hypothesis: for all 805 of 805 PD-TR firms, the INTPERSONSEQ values seen on their PD-TR rows exactly match the INTPERSONSEQ already recorded on that same firm's own row_type = 'PD' master record 6.
Verified conclusion: INTPERSONSEQ on PD-TR rows is the firm's person-sequence identifier (likely a contact/principal person tied to the broker-firm registration), carried down onto every technical-representative row for that firm — not a person-level identifier for the technical representative. This fully explains why 36,815 PD-TR rows collapse to only 483 INTPERSONSEQ values and why all 483 also appear in Agency-type-adjacent/firm records: it is firm-linked metadata, not individual identity.

What remains unresolved
No single field tested here is confirmed as a clean, non-duplicated "one row = one real individual" key for PD-TR. pd_tr_ia_code is the strongest candidate based on its many-to-one relationship with pd_tr_INTTRAGTSEQ and its reuse across firms, but 15.3% NULL coverage and the 60 firms with many TR IDs under a single IA code mean a counting rule based on pd_tr_ia_code would still need further validation (e.g., against the source aa_tbltragent/IA registry) before being adopted as a business metric. No final counting rule is recommended given this unresolved gap.
