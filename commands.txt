Summary
The education table is cleanly structured (zero duplicate keys, 100% match to Agency agents only), but several metrics the user wants to calculate — verification status, qualification meaning, and processing time — cannot be reliably derived due to undocumented codes and extremely sparse date population.

Verified conclusions:
agt_edu_cdc_action contains only I (Insert) and U (Update) — no D (Delete) actions were found, so there is no evidence of deleted-record markers remaining in this table.
Since (INTAGTSEQ, agt_edu_seq) is already confirmed unique with zero duplicates (finding #1), multiple rows do not represent multiple versions/updates of the same education entry — each agt_edu_seq appears exactly once, meaning the table stores the current state of each entry rather than a full update history. The U action likely marks that a given row was modified in place at some point, not that an older version coexists alongside a newer one.
agt_edu_last_updated_time is never earlier than agt_edu_created_time, consistent with a well-formed audit trail.
No CDC action needs to be excluded for standard counting — since no delete markers exist and no duplicate versions exist, a simple COUNT(*) / COUNT(DISTINCT agt_edu_seq) over the whole table already reflects current records. A reliable "current record" filter is therefore the full table itself; no additional filtering by agt_edu_cdc_action is necessary or evidenced as useful.
